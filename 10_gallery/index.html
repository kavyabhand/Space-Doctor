2 · Method

Nothing counts on Beam's word

Most broken Spaces did nothing wrong. Spaces reinstall unpinned dependencies on every rebuild, so code that worked when it shipped now meets gradio 5 and 6, huggingface_hub 1.0, numpy 2, torch 2.6 and Python 3.13. The fix is usually small. Finding it means reading the repo, the traceback and the installed package versions together.

Beam gets all of it in one prompt: the repository with the most relevant files first, Hugging Face's error log, our rebuild log, the exact pip freeze, and the Dockerfile the Space is built from. It answers with a patch, a dated lockfile, or the verdict that the Space can't be fixed honestly. Then we check.

Step 1ReproduceRebuild the untouched Space with the Spaces recipe. It must still fail, or it is not a patient.
Step 2DiagnoseBeam cites the log line that proves the cause, and can ask for any file it was not shown.
Step 3Check the patchEdits must apply and lockfiles must resolve. Failures go straight back to Beam, before any rebuild.
Step 4GuardPatches that delete code, drop functions, swallow errors or change special-token text are rejected.
Step 5Rebuild and callThe Space must boot and its main endpoint must return a non-empty result. If not, Beam tries again at higher effort.
3 · Causes

Why Spaces die, in one call

Beam read the error log of every broken Space in a single long-context call and named the causes, each as a regular expression. We ran its expressions over the logs ourselves, so every count is measured.

4 · Control

Does it take a model?

The obvious alternative needs no model at all: reinstall every dependency as it existed on the day of the Space's last commit, with uv --exclude-newer. We ran it on the same patients, with the same verifier.

Limits

What this does not claim

A rebuild, not Hugging Face's builder.We follow the documented Spaces recipe. CPU Spaces use CPU torch wheels, which share the same Python API. Patched READMEs pin the Python version we tested with, so what deploys is what we verified.
Functional is a smoke test.The main endpoint returned a non-empty result for one real input, the Space's own example file when it ships one. It is not a quality grade, so the outputs are shown for you to judge.
GPU Spaces ran on one NVIDIA A10G,the GPU of Hugging Face's a10g-small. Spaces that ran on a T4 or L4 were verified on it too.
Owners decide.Pull requests went only to Spaces we revived, verified and reviewed, each with its evidence. We changed nothing on anyone's Space ourselves.
